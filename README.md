# «Готовность к эпохе ИИ» — веб-приложение для стенда ICL Системные технологии

Django-приложение для выставочного стенда: посетитель проходит короткий опрос об
использовании и защите ИИ в его организации и получает персональный отчёт с
выявленными рисками, рекомендациями и QR-кодами (в том числе постоянную ссылку
на отчёт и QR на сайт/почту компании).

## Технологии

- Python 3.11+, Django 5.0
- SQLite (файл `db.sqlite3`, без внешней СУБД — рассчитано на локальный ноутбук на стенде)
- Bootstrap-подобная собственная вёрстка (Django-шаблоны + чистый CSS/JS, без сборщиков)
- `qrcode` + `Pillow` — генерация QR-кодов
- `WeasyPrint` (основной) / `reportlab` (автоматический fallback) — генерация PDF-отчёта

## Структура проекта

```
icl_ai_readiness/
├── config/          # настройки Django, корневые urls, wsgi/asgi
├── core/            # SiteSettings (singleton), лендинг (Экран 1)
├── survey/          # Question, AnswerOption, SurveySession, Answer, логика опроса
├── risks/           # RiskCategory, Risk, Recommendation, ScoreInterpretation, отчёт, PDF
├── services/        # Service — услуги компании
├── templates/        # HTML-шаблоны (base, core, survey, report)
├── static/           # CSS и JS
└── media/            # загружаемые файлы (логотип и т.п.)
```

## Установка и запуск (Windows / macOS / Linux)

### 1. Распакуйте проект и перейдите в папку

```bash
cd icl_ai_readiness
```

### 2. Создайте и активируйте виртуальное окружение

Linux/macOS:
```bash
python3 -m venv venv
source venv/bin/activate
```

Windows (PowerShell):
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

> **Важно про WeasyPrint.** Библиотека для качественной генерации PDF из HTML/CSS
> требует системных зависимостей (Pango, Cairo, GDK-Pixbuf). На Windows это иногда
> вызывает сложности при установке. Если `pip install` не смог собрать WeasyPrint
> или PDF не генерируется при запуске — **ничего страшного**: приложение автоматически
> переключится на генерацию PDF через `reportlab` (файл `config/settings.py`,
> переменная `PDF_ENGINE` определяется автоматически при старте). Внешний вид PDF
> в этом случае будет чуть проще, но кнопка "Скачать PDF" будет работать всегда.
>
> Если хотите обязательно получить WeasyPrint-версию PDF на Windows, проще всего
> поставить зависимости через MSYS2 (см. официальную инструкцию WeasyPrint) либо
> развернуть приложение в Docker/WSL2 с Ubuntu, где `apt install libpango-1.0-0
> libpangocairo-1.0-0 libgdk-pixbuf2.0-0` решает вопрос одной командой.

### 4. Настройте переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости отредактируйте:

```bash
cp .env.example .env      # Linux/macOS
copy .env.example .env    # Windows
```

Для демонстрации на стенде значения по умолчанию (DEBUG=True, SQLite) отлично подходят.
Перед реальной публикацией в интернете обязательно смените `SECRET_KEY` и `DEBUG=False`.

### 5. Примените миграции

```bash
python manage.py migrate
```

Эта команда создаст базу `db.sqlite3` и **автоматически заполнит её стартовыми
данными**: 4 категории риска, 15 вопросов опроса с вариантами ответов, 34 риска,
10 рекомендаций, 7 услуг компании, 3 интерпретации уровня зрелости и запись
глобальных настроек сайта. Дополнительных действий для наполнения БД не требуется.

### 6. Создайте суперпользователя для входа в админку

```bash
python manage.py createsuperuser
```

Введите логин, e-mail (можно пропустить) и пароль.

### 7. Запустите сервер

```bash
python manage.py runserver 0.0.0.0:8000
```

Откройте в браузере:
- **`http://localhost:8000/`** — стартовая страница стенда (Экран 1)
- **`http://localhost:8000/admin/`** — админка Django

Для показа на стенде рекомендуется открыть браузер в полноэкранном (kiosk) режиме,
например в Chrome: `chrome --kiosk http://localhost:8000/`.

## Как редактировать контент через админку

Все тексты, вопросы, риски, рекомендации и услуги можно менять **без единой
правки кода** — весь контент хранится в базе данных.

- **`/admin/core/sitesettings/`** — заголовок и текст лендинга, текст кнопок,
  заголовок страницы результата, логотип, корпоративный цвет, контакты компании,
  включение/выключение сбора персональных данных.
- **`/admin/survey/question/`** — вопросы опроса. Для каждого вопроса можно
  редактировать текст, порядок показа, обязательность и (для чисел) диапазон.
  Варианты ответов редактируются прямо на странице вопроса (инлайн) — там же
  настраиваются теги категорий риска и вес для скоринга.
  Порядок вопросов задаётся полем **"Порядок показа"**.
- **`/admin/risks/risk/`** — реестр рисков: название, описание, критичность,
  публичный кейс/статистика со ссылкой на источник, привязка к категориям и
  к услуге компании, которая закрывает этот риск.
  Порядок показа регулируется полем **"Порядок / приоритет"**.
- **`/admin/risks/recommendation/`** — общие рекомендации, показываемые в
  каждом отчёте.
- **`/admin/risks/scoreinterpretation/`** — тексты интерпретации итогового
  балла (0–30, 31–60, 61–100).
- **`/admin/services/service/`** — услуги компании со ссылками на сайт
  icl-st.ru, которые показываются в конце отчёта.
- **`/admin/survey/surveysession/`** — журнал всех прохождений опроса
  (для просмотра статистики посещений стенда и оставленных контактов).

Любой из перечисленных элементов можно временно скрыть, не удаляя, сняв
галочку **"Активен"/"Активна"** — это удобно, если нужно быстро протестировать
другой набор вопросов или рисков во время подготовки к выставке.

## Пользовательский сценарий

1. **`/`** — лендинг с логотипом, лозунгом и двумя одинаковыми кнопками «Нет»,
   ведущими к опросу.
2. **`/survey/start/`** → **`/survey/<uuid>/question/<N>/`** — опрос по одному
   вопросу с прогресс-баром.
3. Если в настройках включён сбор контактов — **`/survey/<uuid>/contacts/`**
   перед показом результата.
4. **`/survey/<uuid>/result/`** — "горячий" результат сразу после опроса,
   с QR-кодами на постоянную ссылку отчёта и кнопками "Скачать PDF" /
   "Начать новый опрос".
5. **`/report/<uuid>/`** — постоянная публичная страница отчёта (без QR на
   саму себя, но с QR на сайт компании и на письмо на office@icl-st.ru).
6. **`/report/<uuid>/pdf/`** — тот же отчёт в виде PDF-файла.

## Проверка работоспособности перед выставкой

Рекомендуемый ручной прогон перед показом на стенде:

1. Откройте `/`, нажмите любую из кнопок «Нет».
2. Пройдите весь опрос до конца, отвечая на вопросы в разных комбинациях
   (полезно один раз пройти "плохим" сценарием, один раз — "хорошим", чтобы
   увидеть разные уровни готовности и наборы рисков).
3. Если включён сбор контактов — заполните форму и убедитесь, что валидация
   e-mail/телефона работает.
4. На странице результата проверьте, что QR-код открывает корректную ссылку
   `/report/<uuid>/` на телефоне.
5. Нажмите "Скачать PDF" и убедитесь, что файл открывается и содержит те же
   риски, баллы и рекомендации.
6. Откройте `/report/<uuid>/` напрямую (без QR на себя) и проверьте блок
   с QR на сайт и на почту компании в самом низу страницы.
7. Нажмите "Начать новый опрос" и убедитесь, что сценарий повторяется корректно
   для следующего посетителя.

## Возможные проблемы и решения

- **PDF не открывается / ошибка при генерации.** Проверьте, какой движок PDF
  используется — при недоступности WeasyPrint автоматически используется
  reportlab, ошибок быть не должно. Если ошибка всё же возникает, проверьте
  логи `runserver` в терминале.
- **Логотип не отображается.** Загрузите файл логотипа через
  `/admin/core/sitesettings/` (поле "Логотип"), либо убедитесь, что папка
  `media/branding/` доступна для записи.
- **После добавления нового вопроса он не появляется в опросе.** Проверьте,
  что у вопроса установлена галочка "Активен" и уникальное поле "Порядок показа".
